# 인공와우 인터랙티브 합주실 — 클릭 가능한 프로토타입

기준 문서는 팀의 `인공와우 인터랙티브 합주실 구성안.md`(화면과 동작)와 `DESIGN.md`(0절 Project Overrides가 원본보다 우선)예요. 두 문서는 이 저장소에 들어 있지 않아요.
구성안의 각 요구사항을 어디까지 구현했는지는 [`CHECKLIST.md`](CHECKLIST.md)에 정리했어요.

> **지금은 시험판이에요.** 실제 악기 녹음 대신 악기마다 독립된 **핑크노이즈**가 나요. 음높이가 있는 소리(합성 멜로디)는 없어요.
> 곡 1은 「Happy Birthday to You」이고, **곡 2는 아직 정하지 않았어요**. 화면에는 "곡 2 (미정)"으로만 표시해요.

## 실행 방법

필요한 것: Node.js 20 이상(개발 시 v24.10에서 확인).

```bash
cd prototype
npm install
npm run dev
```

브라우저에서 <http://localhost:5173> 을 열어요. 첫 화면의 **[소리 켜기]**를 눌러야 소리가 나요(브라우저 정책).

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사(`tsc -b`) + 배포용 빌드(`dist/`) |
| `npm run preview` | 빌드 결과 미리 보기 |
| `npx tsc -b` | 타입 검사만 |

### 배포 (GitHub Pages)

`main` 브랜치에 푸시하면 [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)이 빌드해서 GitHub Pages에 올려요. 저장소 Settings → Pages의 Source는 **GitHub Actions**여야 해요. 빌드는 상대 경로(`base: './'`)와 해시 라우터(`#/room/hbd`)를 써서 하위 경로에서도 서버 설정 없이 동작해요. 외부 계정·API 키·서버는 쓰지 않아요.

## 구조

```
src/
  audio/
    engine.ts        오디오 엔진(구성안 7.5 스케치 구현): 스템 그래프, 솔로·켜고 끄기, 구간 반복, 지연 보정, 클립
    placeholder.ts   핑크노이즈 자리표시 스템(편곡안의 박 패턴으로 크기만 끊음)
    timeline.ts      RMS·온셋 타임라인(애니메이션·레인용)
    probeAudio.ts    단서 질문 편집본(원본·어택·밝기·높낮이·리듬·강조 5종) 자리표시 + 공개 표 설명
    useEngine.ts     React 훅
  config/
    songs.ts         곡 설정 ← 실제 음원 경로를 여기에 넣는다
    probes.ts        단서 질문 세트 구성·칩·단서 대응표
  store/             localStorage 저장(프로필·로그·응답·리포트), 요약 규칙, 내보내기
  components/        공용 UI, 악기 일러스트·카드, 시각화(레인·탐색·화면-소리 맞추기)
  screens/           화면
```

### 오디오 그래프

```
스템(카혼·베이스·트럼펫·베이스 옥타브 보조)
  소스 → 뮤트 게인(솔로/끄기, 20 ms 램프) → 사용자 게인(악기 크기 + 솔로 크기 맞춤)
       → 저음 쉘프(저음 도움) → (넓게 펼침일 때만 패너, +3.01 dB 보상) → 분석기
  → EQ 저음(500 Hz 쉘프) → EQ 또렷함(1.7 kHz 또는 3 kHz 피킹) → 좌우 밸런스 → 마스터 크기 → 출력
단서 질문·보정 클립 → (EQ 뒤로 들어감) 밸런스 → 마스터   ← 4.4: 마스터·라우팅만 적용
```

모든 시각화와 연주자 애니메이션은 `engine.songTime()` 하나로 "지금 스피커에서 나는 곡 위치"를 구해요(`getOutputTimestamp` 우선, 없으면 `baseLatency + outputLatency`, 그리고 사용자 오프셋).

## 핑크노이즈를 실제 음원으로 바꾸는 방법

1. 파일을 `prototype/public/audio/`에 넣어요. 파일명은 구성안 8.2절 규칙을 따라요.
   - 스템: `hbd_stem_cajon.flac`, `hbd_stem_bass.flac`, `hbd_stem_trumpet.flac`, `hbd_stem_bass_oct.flac` (곡 2도 같은 형식)
   - 모든 스템은 **길이와 시작 샘플이 같아야** 해요(8.3절). 모노 권장(스테레오면 앱이 모노로 섞어요).
   - FLAC가 안 되는 브라우저가 있으면 AAC(.m4a)도 돼요(`decodeAudioData`가 읽는 형식이면 무엇이든).
2. [`src/config/songs.ts`](src/config/songs.ts)에서 해당 스템의 `url`을 채워요.
   ```ts
   stems: {
     cajon:   { url: '/audio/hbd_stem_cajon.flac' },
     bass:    { url: '/audio/hbd_stem_bass.flac' },
     trumpet: { url: '/audio/hbd_stem_trumpet.flac' },
     bassOct: { url: '/audio/hbd_stem_bass_oct.flac' },
   },
   ```
   `url`이 `null`인 스템만 핑크노이즈로 남아요. 스템 일부만 먼저 바꿔도 돼요.
3. 같은 파일에서 `bpm`, `startOffsetSec`(카혼 예비박 첫 박이 파일의 몇 초인지), `lines`(1–4줄 구간, 박 단위), `calibLoopBeats`, `bassLoopBeats`를 녹음에 맞춰요. 클릭 트랙에 맞춰 녹음했다면 bpm과 시작 위치만 맞추면 돼요. `placeholderDurationSec`은 자리표시 전용이라 실제 파일이 있으면 무시돼요.
4. (선택) 오프라인 분석 타임라인(8.1 F, `tl_hbd_trumpet.json` 등)이 있으면 `timelineUrl`에 넣어요. 형식: `{ "hop": 0.01, "rms": [...], "onsets": [{ "t": 1.23, "strength": 0.8, "kind": "slap" }], "pitch": [...] }`. 없으면 앱이 불러올 때 RMS와 온셋을 직접 계산해요(음높이 선은 JSON이 있어야 보여요).
5. 단서 질문 편집본(8.1 D)은 [`src/audio/probeAudio.ts`](src/audio/probeAudio.ts)의 `PROBE_FILES`에 경로를 넣어요(`p_hbd_orig.wav` 등). `PROBE_MANIFEST`의 설명(공개 표·내보내기에 쓰임)도 실제 처리 내용으로 고쳐요.
6. 실제 파일이 모두 들어가면 설정의 "자리표시 소리 모양"은 의미가 없어지니 지워도 돼요.

자리표시 스템은 피크를 −15 dBFS로 맞췄어요. 실제 스템은 구성안 8.2절대로 기본 믹스 −18 LUFS에 맞춘 같은 이득으로 내보내면 앱이 따로 손대지 않아요.

## 가정 (구성안에서 정하지 않았거나 프로토타입이라 정한 것)

소리
- **자리표시 소리 모양.** 기본은 "박자에 맞춰 끊기는 핑크노이즈"예요. 구성안 5.3의 편곡 시작점에서 **리듬만** 가져와 크기를 끊었고, 음높이는 없어요. 레인·연주자 애니메이션이 실제로 소리와 같이 움직이게 하려는 선택이에요(설계 원칙 5). 설정에서 "계속 나는 잡음"으로 바꿀 수 있어요.
- 자리표시 템포·길이는 임시값이에요: 곡 1 90 BPM·35초, 곡 2 100 BPM·42초(구성안은 60–90초).
- 곡 2는 4/4로만 가정했어요(구성안의 곡 2 카혼·베이스 패턴). 트럼펫 자리는 줄마다 고른 4분음표예요. 곡이 정해지면 `src/config/songs.ts`와 `src/audio/placeholder.ts`의 `score44`를 고쳐요.
- 자리표시 스템은 피크 −15 dBFS로 맞췄고, 단서 질문 편집본은 RMS −28 dBFS로 맞췄어요(로빙 없음). 컴프레서·리미터는 쓰지 않았어요(5.4).
- "저음 도움 – 저음 키우기"는 베이스 스템에 300 Hz 저역 쉘프 +6 dB예요(구성안은 주파수를 정하지 않음).
- 단서 질문의 **높낮이 편집본은 진짜가 아니에요.** 핑크노이즈엔 음높이가 없어서 트럼펫 소리의 대역만 낮춘 대용이고, 리포트 공개 표에 그렇게 적었어요.

화면·동작
- 합주실의 화면-소리 맞추기 카드는 처음 시각화를 켤 때 **먼저 "맞춰 볼까요?"로 물어요.** 맞추는 동안 클릭음만 나야 해서 음악이 멈추기 때문이에요.
- 눈 가리고 듣기 중에는 시각화도 숨겨요(레인에 악기 이름이 보이면 의미가 없어서).
- 프리셋("멜로디 또렷하게" 등)은 그 악기만 +6 dB로 바꾸고 나머지는 지금 값을 유지해요. [이 곡에 저장]을 눌러야 저장돼요.
- 듣기 우선 흐름은 "이번 세션에 이 곡을 처음 열 때"만 나와요(새로고침하면 다시 나옴).
- 단서 질문 슬라이더 시작 위치는 10–90 사이 무작위예요.
- 안내 카드는 곡 1에 5개, 곡 2에는 제목과 상관없는 일반 카드 3개를 썼어요.
- 리포트의 "그 질문만 다시 들어 보기"는 리포트 안의 해당 단서 카드에서 다시 듣는 것으로 대신했어요.

기술
- 해시 라우터(`#/room/hbd`)를 써요. 정적 호스팅에서 서버 설정이 필요 없어요.
- 웹폰트(Pretendard, Gmarket Sans)는 jsDelivr CDN에서 불러와요. 오프라인이면 시스템 폰트로 보여요.
- `#/dev/instruments`는 악기 UI의 모든 상태를 보는 개발용 화면이에요(배포 빌드에서는 빠져요).

## 남은 결정 사항

1. **곡 2 선정.** 아직 정하지 않았어요. 정해지면 `src/config/songs.ts`의 `song2.title`, `undecided: false`, 박자·bpm·줄 구분을 고쳐요. 그 곡의 안내 카드 문구도 필요해요(`src/screens/room/GuideCards.tsx`).
2. **실제 녹음 6스템 + 옥타브 보조 2개**와 단서 질문 편집본 10개(구성안 8.1). 넣는 방법은 위 "핑크노이즈를 실제 음원으로 바꾸는 방법"을 보세요.
3. **또렷함 기본 대역(1.7 kHz vs 3 kHz)**은 파일럿 비교로 정해요(4.2). 보정 ④에 비교 옵션이 있어요.
4. **안내 카드·성찰 칩 문구**는 고령 사용자 파일럿에서 다듬을 필요가 있어요.
5. **지연 실측**(실기기·블루투스·CI 스트리밍)은 1주차 기술 시험으로 해야 해요(10.3). 설정 화면과 내보내기 파일에 기기의 `baseLatency`/`outputLatency`가 남아요.
6. 시각화 기본값(곡 처음엔 끔 → 레인), 어두운 배경, 카혼 박 표시 켬/끔은 파일럿 비교 항목이에요(7.3, 5.2).
7. 연주자 일러스트는 지금 SVG예요. 팀 일러스트(Clay 톤 3D)로 바꾸려면 `src/components/instruments/figures.tsx`의 포즈 구조(대기 / 치기·튕기기 / 연주 / 내림)를 그대로 유지하면 돼요.

## 검증 기록 (2026-10-23)

- `npm run build`(타입 검사 `tsc -b` 포함) 통과. `npx oxlint src`는 오류 0개, React 스타일 경고 28개(동작에는 영향 없음).
- 내장 브라우저에서 시작 → 보정 ①–⑥·요약 → 합주실(곡 1, 곡 2) → 단서 질문 세트 1(연습 + 8문항 + 성찰) → 리포트 → 설정 → 정보를 직접 눌러 봤어요. 새로고침 후 모든 화면을 돌았을 때 콘솔 오류 0개.
- 핑크노이즈 출력 실측(마스터 출력 RMS):
  - 계속 나는 잡음 기준 전체 −26.5 dB → 마스터 −6 dB 시 −32.6 dB
  - 트럼펫 솔로 −31.3 dB(솔로 크기 맞춤 끔) / −25.9 dB(켬)
  - 다른 두 악기 −12 dB 시 −31.0 dB
  - 저음 EQ +6 dB 시 −22.1 dB, [원래 소리]를 켜면 −26.5 dB로 복귀
  - 일시정지 시 무음(−120 dB)
- 솔로·끄기: 꺼진 스템의 분석기 값 −120 dB(무음) 확인. 번갈아 듣기 2마디(4초) 간격 확인. 3줄 구간 반복 확인.
- 375×812 모바일, 1280×900 데스크톱, 다크 모드 스크린샷 확인. 자동 접근성 검사(대비 4.5:1, 글자 14px 이상, 터치 44px 이상, 가로 스크롤 없음)를 전 화면에서 통과.
- 확인하지 못한 것: 실제 iPhone/Android 기기, 블루투스·CI 프로세서 직결, 화면 낭독기(VoiceOver/TalkBack) 실제 사용, 실제 녹음 파일 디코딩.
